# 一个功能，从头到尾

[English](the-loop.md) | 简体中文

这篇用一个虚构的小项目 **菜谱盒**（一个保存菜谱的小网页应用），带一个功能走完整个循环。下面的话都是你实际会贴的样子。

## 0. 搭建

```bash
claude-relay-loop/init.sh ~/code/recipe-box --lang zh --name "菜谱盒"
```

## 1. 起步（Cowork）

用 Cowork 打开 `~/code/recipe-box`，说：

> 读一下 COWORK.md，带我开始

Cowork 先读文件夹，然后每次问几个问题：这个应用做什么用、谁在用、第一个有用的结果是什么。它根据你的回答写好 `roadmap.md`，提出第一个功能。你确认之后，Cowork 写好 `features/F001-ingredient-search/plan.md`，并在 `pipe/cowork/latest.md` 里写下第一张任务卡：

```markdown
| 编号 | 内容 | 负责人 | 状态 |
|---|---|---|---|
| F001-T01 | 按食材搜索菜谱 | 本人 | 已授权 |

### F001-T01 — 按食材搜索菜谱
- 做什么：菜谱列表上加一个搜索框，按一种或几种食材筛选。
- 参考：features/F001-ingredient-search/plan.md §3、§5
- 范围与限制：只按食材名匹配；不做模糊匹配，也不管用量和单位。
- 验收：输入「鸡蛋，面粉」只显示同时用到这两样的菜谱；清空搜索框，显示全部菜谱。
- 前置条件 / 待定问题：无
- 计划审阅：跳过
- 状态：已授权（负责人，2026-10-14）
```

然后它请你提交规划文件（Claude Code 可能是在一份新克隆的仓库上开工），再给你：

```text
F001 按食材搜索 — 主会话开工
任务卡：F001-T01（pipe/cowork/latest.md › 下一步）
计划审阅：跳过（写完计划直接开子会话）
先读：features/F001-ingredient-search/plan.md
备注：搜索在前端做就行，菜谱不多。
```

## 2. 主会话（Claude Code）

在 Claude 桌面版里对同一个文件夹打开 Code 标签页，新开一个会话，把这段话贴进去。主会话会：

1. 把自己改名为 **F001 按食材搜索**；
2. 读任务卡、功能方案和代码；
3. 写好 `pipe/claudecode/plans/2026-10-14-F001-T01-ingredient-search.md` 并提交；
4. 开一个标题为 **F001-T01 执行：按食材搜索** 的子会话，说明大致是这样：

```text
你是任务卡 F001-T01 的执行子会话。
计划：pipe/claudecode/plans/2026-10-14-F001-T01-ingredient-search.md
分支：feat/F001-T01-ingredient-search（从 main 拉出）
先读 CLAUDE.md（有 CLAUDE.local.md 的话也读），照其中「子会话」一节做。
就在当前目录、这个分支上做：不要建 worktree。
一个任务一个任务地执行计划。每做完一个任务，更新 pipe/claudecode/latest.md 和当天日志，和这个任务的改动一起提交。
整份计划做完后，跑全量测试，然后停下汇报：提交、测试条数、偏离、没验证的地方。
不要合并、开 pull request 或删分支。
```

然后它就等着。它不轮询：子会话停下时，桌面版会叫醒它。

## 3. 子会话（Claude Code）

子会话一次做计划里的一个任务：先写一个会失败的测试，再写实现让它通过，然后更新交接、提交。你随时可以在侧边栏里打开它，看它做，或者和它说话。做完后，它向主会话汇报。

## 4. 核对和汇报（主会话）

主会话不会照单全收。它自己看 diff，自己跑全量测试，读 `pipe/claudecode/latest.md`。哪里不对，就告诉子会话改什么，再等它。然后向你汇报：做了什么、测试结果、偏离、哪些没验证。合并之前会先问你。

如果这个功能还有第二张已授权的卡，主会话这时会接着写那张卡的计划，再开一个子会话，这些都在同一个主会话里做。

## 5. 收尾：发给 Cowork 的话

已授权的卡都做完并合并后，主会话给你：

```text
F001 按食材搜索做完了。
任务卡：F001-T01。已合并进 main：是（4f2c9e1）。
测试：全量通过（48 条）。
请读：这次会话还没读过 COWORK.md 的话先读它，再读 pipe/claudecode/latest.md › 已完成 / 已决定（偏离）、需要对方知道 / 回答的事。
未验证：没试过 500 个以上的菜谱。
需要你定：偏离（搜索也会匹配菜谱标题）接不接受？
请更新方案状态、任务表和 roadmap.md，然后给我下一个功能的「发给 Claude Code 的话」。
```

## 6. 回到 Cowork

把它贴进 Cowork。Cowork 读交接，问你偏离接不接受，在方案、任务表和 roadmap.md 里把 F001 标成完成，记下日志，再和你一起规划 F002。最后它给出下一段「发给 Claude Code 的话」，由一个新的 Claude Code 会话接手。

## 没有桌面版时

Claude Code CLI 和 IDE 插件开不了子会话。这时主会话会把第 2 步里的说明放进代码块打印出来。你在同一个文件夹里另开一个会话，贴进去；等它做完，回到主会话说一声做完了。主会话再照第 4 步核对。

## 出问题时

- **子会话卡住了，或者计划有错。** 它会停下来向主会话汇报，不会自己发挥。主会话改计划，或者来问你。
- **冒出一个规划上的问题**（任务卡不清楚，范围要改）。Claude Code 把它写进「需要对方知道 / 回答的事」，然后停下。你把问题带到 Cowork，等 Cowork 改好任务卡，再接着做。
- **会话太长了。** 两边都会在稳定点建议换新会话。什么都不会丢，因为一切都在文件里。
