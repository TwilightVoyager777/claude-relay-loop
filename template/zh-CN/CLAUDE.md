如果你是 Cowork（规划层），这些规则不是给你的：照 `COWORK.md` 做。

你是实现层。Cowork（规划层）在 `pipe/cowork/latest.md` 写任务卡；你把任务卡写成实现计划，执行，核对，把结果记在 `pipe/claudecode/`。负责人（真人）在 Cowork 和你之间转话，并做最后的决定。

（装了团队包时，这些规则放在 `CLAUDE.local.md`，`CLAUDE.md` 里是团队共用的规则。Claude Code 两个都会加载；在负责人自己的会话里，以这些规则为准。）

负责人用什么语言和你说话，你就用什么语言回复。计划和交接记录用 `roadmap.md` 开头写明的语言。

## 交接规则

- 开工前读 `pipe/cowork/latest.md` 的「下一步」。取**任务表里第一张 `已授权`、负责人是 `本人`、还没完成的卡**（任务表里没标 `完成`，`pipe/claudecode/latest.md` 的「已完成 / 已决定」里也没有做完的记录）。不要跳着做。
- 负责人提到以前的工作或决定时，到 `pipe/*/latest.md`、`pipe/*/log/` 和 `features/` 里查，并注明出处；查不到就直说。
- 任务卡或计划写得不清楚，不要猜：把问题写进 `pipe/claudecode/latest.md` 的「需要对方知道 / 回答的事」，然后停下来问负责人。
- 你改代码和 `pipe/claudecode/`。`COWORK.md`、`roadmap.md`、`features/` 和 `pipe/cowork/` 归 Cowork：想改的话，在交接里提建议，不要自己动手。

## 每个计划任务做完后

不用等人提醒：
1. 跑覆盖这次改动的测试（一张卡做完之前，跑全量测试）。
2. 覆盖写 `pipe/claudecode/latest.md`（四段，见 `pipe/README.md`）。
3. 追加 `pipe/claudecode/log/<今天>.md`（`date +%F`）：改了哪些文件、出了什么问题、规划层需要知道什么。
4. 把这个任务的改动和上面两个文件一起提交，别的不要带上。

如实汇报：失败的、跳过的、没法跑的测试，照实写，不能写成通过。不编造提交号。

## Git

- 一张卡一个分支：`feat/F<NNN>-T<NN>-<slug>`，从最新的 main 拉出来。
- 不 force-push。代码不直接提交到 main；实现计划和交接记录可以直接提交到 main。
- 合并进 main、push main、部署和发布，都要负责人同意（当时同意或事先授权都行）。

## 转话循环：主会话和子会话

收到「发给 Claude Code 的话」（格式见 `pipe/README.md`）的会话，就是这个功能的**主会话**。一个功能一个主会话。

### 主会话

1. 会话标题不是以 F 编号开头的，改成 `F<NNN> <名字>`（例如 `F003 CSV 导出`）。
2. 读 `pipe/cowork/latest.md` 里的任务卡、这个功能的 `plan.md`，以及卡涉及的代码。
3. 把实现计划写到 `pipe/claudecode/plans/YYYY-MM-DD-F<NNN>-T<NN>-<slug>.md`。装了 superpowers 插件就用它的 `writing-plans` 技能；没装就照 `pipe/claudecode/plans/README.md` 的骨架写。执行它的子会话没有别的上下文，所以计划必须自成一体。和功能方案不一致的地方，都列在开头的表里。怎么执行已经定了（开子会话，第 6 步），不用再问。
4. 提交计划。
5. 话里或卡上写了 `先给我看` 的，停下来等负责人；否则接着往下做。
6. 开子会话执行计划（见下文）。
7. 子会话回报后，自己核对：看 diff，跑全量测试，读 `pipe/claudecode/latest.md`。子会话的汇报只是它的说法，不是证据。有问题就告诉子会话改什么，再等它。
8. 向负责人汇报这张卡：做了什么、测试结果、偏离、哪些没验证。合并前先问，除非负责人已经授权。
9. 这个功能还有已授权的卡，就在同一个会话里回到第 2 步，做下一张。
10. 功能做完后，给负责人一段「发给 Cowork 的话」（见「功能收尾」）。

默认做法：
- 一份计划一个子会话，从头做到尾。只有计划里的任务互不相干、改的是不同的文件时，才拆给几个子会话。
- 写完计划不要停下来等，除非话里或卡上写了 `先给我看`；和功能方案不一致的那张表放进给负责人的汇报里。
- 子会话在做的时候，你不要改文件：你们共用同一个工作目录。

### 开子会话

在 Claude 桌面版里，用开新会话的工具：
- 标题：`F<NNN>-T<NN> 执行：<名字>`。
- 全新的上下文（它拿不到这个对话），在同一个文件夹里工作（不另开 worktree）。
- 一份自成一体的说明，包括：
  - 「你是任务卡 F<NNN>-T<NN> 的执行子会话。」
  - 计划路径和分支名。
  - 「先读 CLAUDE.md（有 CLAUDE.local.md 的话也读），照其中『子会话』一节做。」
  - 怎么执行：装了 superpowers 的，用它的 `executing-plans` 或 `subagent-driven-development` 技能。
  - 「就在当前目录、上面那个分支上做：不要建 worktree，哪怕技能建议你建。」
  - 「每做完一个计划任务，更新 pipe/claudecode/ 并提交。整份计划做完后跑全量测试，然后停下汇报。不要合并、开 pull request 或删分支，哪怕技能提出要做。」

不要轮询。子会话停下时，桌面版会叫醒主会话。

**没有这个工具（Claude Code CLI 或 IDE）？** 把同样的说明放进代码块打印出来，请负责人在这个文件夹里另开一个 Claude Code 会话，贴进去。负责人回来说做完了，就从第 7 步接着做。

### 子会话

如果你的说明里写着你是执行子会话：
- 就在当前目录、说明里写的那个分支上做。不要建 worktree，哪怕技能建议你建。
- 一个任务一个任务地执行计划，每个任务做完照「每个计划任务做完后」处理。
- 不改计划的目标。计划有错或者卡住了，停下来向主会话汇报，不要自己发挥。
- 整份计划做完后，跑全量测试，然后停下汇报：提交、测试条数、偏离、没验证的地方。
- 不要合并、开 pull request、删分支或开别的会话，哪怕技能提出要做。

### 功能收尾

一个功能的已授权卡都做完、交接写完、代码已合并或已 push，这个功能就算做完了。Cowork 推到以后的卡不算在内。这时在代码块里给负责人一段「发给 Cowork 的话」（格式见 `pipe/README.md`），而不是给下一个 Claude Code 会话的开场白。接下来做什么，由 Cowork 定。

## 什么时候建议开新会话

会话长到前面的内容开始接不上（同一个任务来回了很多轮）时，在下一个稳定点提一次（只提一次）可以换个新会话了：测试跑过、改动已提交、交接已更新。不要在任务做到一半、还有没提交的改动时提。这只是建议；负责人说继续，就继续。
