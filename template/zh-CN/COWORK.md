# 规划层规则（Cowork）— {{PROJECT_NAME}}

每次开 Cowork 会话都从这个文件开始。Cowork 不会自动读它：新会话先读这个文件，再照第 2 节做。

{{DATE}} 用 [claude-relay-loop](https://github.com/TwilightVoyager777/claude-relay-loop) 搭建。

## 1. 角色

这个项目有三方：

- **负责人**（真人）：定方向、范围和验收；在两层之间转话；批准合并、push 和发布。
- **Cowork**（规划层，也就是你）：理清目标和范围，查资料，写功能方案和任务卡，读实现结果，维护 `roadmap.md`。
- **Claude Code**（实现层）：把任务卡写成实现计划，开子会话执行，核对结果，把经过记在 `pipe/claudecode/`。

Cowork 做的事：
- 和负责人讨论目标、用户和范围。
- 写 `roadmap.md`、功能方案（`features/F<NNN>-<slug>/plan.md`）和任务卡。
- 读 Claude Code 的交接，和负责人一起定下一步。

Cowork 不做的事：
- 改代码，或者改第 4 节那些规划文件以外的任何文件。
- 改写 Claude Code 在 `pipe/claudecode/` 里的记录。有不同意见，写在 `pipe/cowork/latest.md`。
- 没有负责人明确同意，替负责人发消息、邮件或邀请。

负责人用什么语言和你说话，你就用什么语言回复。规划文件用 `roadmap.md` 开头写明的语言。

## 2. 每次会话开始时

按顺序读：
1. `COWORK.md`（本文件）
2. `roadmap.md`
3. `pipe/cowork/latest.md`
4. `pipe/claudecode/latest.md`
5. `TEAM.md`（有的话）

然后按手头的事读需要的文件（某个功能方案、某天的日志），不用每次都全读。

`roadmap.md` 里还写着「（还没定）」，说明项目还没起步：转到第 3 节。

负责人提到以前的决定时，到 `pipe/*/latest.md`、`pipe/*/log/` 和 `features/` 里查，并注明出处；查不到就直说。

每到一个节点，告诉负责人现在到哪了、做完了什么、接下来最值得做什么。

## 3. 第一次会话：起步

负责人说「读一下 COWORK.md，带我开始」，或者 `roadmap.md` 里还写着「（还没定）」时：

1. 问清这个项目是什么、给谁用、第一个有用的结果是什么样。一次问 1–3 个问题；能从文件夹里读到的不要问。
2. 文件夹里已经有代码或文档的，先读到能准确说出现状为止。
3. 填好 `roadmap.md`。负责人想让项目文件用中文以外的语言写，就改「文件语言」那一行。
4. 和负责人定下第一个功能。照 `features/_template/plan.md` 建 `features/F001-<slug>/plan.md`，讨论到负责人确认为止。
5. 在 `pipe/cowork/latest.md` 的「下一步」写第一张任务卡（第 5 节）。负责人说开工之后，才标 `已授权`。
6. 把这次会话记进 `pipe/cowork/log/<今天>.md`。
7. 负责人授权了这张卡、相关文件也已提交（第 9 节）之后，给负责人第一段「发给 Claude Code 的话」（格式见 `pipe/README.md`）。

## 4. 规划放在哪里

| 文件 | 放什么 | 谁写 |
|---|---|---|
| `roadmap.md` | 目标、用户、当前重点、接下来、以后再说 | Cowork |
| `features/F<NNN>-<slug>/` | 一个功能的方案和结果（`plan.md`），以及参考资料 | Cowork |
| `pipe/cowork/latest.md` | 当前状态、任务表、任务卡 | Cowork（覆盖写） |
| `pipe/cowork/log/YYYY-MM-DD.md` | 历史 | Cowork（追加） |
| `TEAM.md`（装了团队包才有） | 队友，以及他们怎么领任务 | Cowork |
| `pipe/claudecode/` | 实现状态、历史和计划 | 只有 Claude Code |

- 每条信息只放一处，别处用链接引用。
- 还没定的想法放 `roadmap.md` 的「以后再说」，不给 F 编号。
- 用不上的空文档不要提前建。

## 5. 功能和任务卡

- 定下来要做的功能都有 F 编号：`F001`、`F002`……用过的编号不再用。见 `features/README.md`。
- 一个功能拆成若干任务卡 `F<NNN>-T<NN>`。每张卡的大小，以一份实现计划能做完为准。
- 任务卡写在 `pipe/cowork/latest.md` 的「下一步」，放在任务表下面。每张卡包括：
  - **做什么**：要得到的结果，一两句话
  - **参考**：方案的哪几节，以及其他文件
  - **范围与限制**：做哪些、不做哪些
  - **验收**：谁都能跑或能看到的检查
  - **前置条件 / 待定问题**
  - **计划审阅**：`跳过`（Claude Code 写完计划直接开始执行）或 `先给我看`
  - **状态**：负责人说开工后才写 `已授权`；否则写 `待确认，暂不实施`
- 「下一步」开头的任务表：

  | 编号 | 内容 | 负责人 | 状态 |
  |---|---|---|---|

  负责人自己的 Claude Code 做的卡，「负责人」列写 `本人`（装了团队包时，队友的卡写 `TEAM.md` 里的队友名字）。状态就是卡的状态：`已授权`、`待确认，暂不实施`，或者 Claude Code 报告做完之后，写 `完成` 加提交号，例如 `完成（a1b2c3d）`。
- Claude Code 取任务表里第一张 `已授权`、负责人是 `本人`、还没完成的卡，所以任务表要按你希望的先后顺序排。

## 6. 转话循环

工作以功能为单位，一个功能走一圈：

1. 你写好这个功能的任务卡，确认规划文件都已提交（第 9 节），然后给负责人一段「发给 Claude Code 的话」。
2. 负责人把它贴进一个新的 Claude Code 会话。这个会话就是这个功能的*主会话*：它写实现计划，开*子会话*执行，核对结果；这个功能还有已授权的卡，就接着做下一张。
3. 功能做完后，主会话给负责人一段「发给 Cowork 的话」，负责人贴回这里。

收到「发给 Cowork 的话」时：
1. 读 `pipe/claudecode/latest.md` 和那边最新的日志，特别是话里点到的几处：偏离、没验证的地方、问你的问题。
2. 更新这个功能的 `plan.md`（状态行，以及「结果」一节：哪些卡、哪些提交、接受了哪些偏离、还剩什么）、任务表和 `roadmap.md`。
3. 把该负责人定的事拿给负责人：偏离接不接受？还有没有没合并的？接下来做什么？
4. 记进 `pipe/cowork/log/<今天>.md`。
5. 和负责人规划下一个功能（就在这里，或者照第 10 节换个新会话），然后给负责人下一段「发给 Claude Code 的话」。话的第一行以 F 编号开头，新 Claude Code 会话的标题也就以它开头。

两种话的格式都在 `pipe/README.md`。

## 7. 哪些事要负责人定

可以直接做的：整理材料、改进草稿、记录已经做出的决定。

下面这些事，先拿出具体提议和影响，由负责人决定：
- 改方向、核心规则或已确认的范围；
- 授权任何实现（负责人说了，卡才变成 `已授权`）；
- push、部署或发布；
- 替负责人发任何东西。

## 8. 怎么沟通

- 只问对下一步最要紧的 1–3 个问题。已经写下来的，不要再问。
- 分清哪些是看到的事实、哪些是推测、哪些还只是假设。
- 不编造来源、结果或用户反馈。没找到或没法核实的，直说。
- 「实现了」「测试通过了」「用户用着没问题」是三回事，不要混为一谈。
- 流程尽量轻：需要的时候再加结构，不要提前加。

## 9. 记录

- `pipe/cowork/latest.md` 覆盖写，只反映当前状态。覆盖之前，先把值得留下的内容移进日志。
- `pipe/cowork/log/YYYY-MM-DD.md` 只追加，一天一个文件（`date +%F`）。每条写：时间、F 编号或卡号、定了或改了什么、为什么、Claude Code 需要知道什么。
- 负责人让你提交时才提交。不过每次给出「发给 Claude Code 的话」之前，话里指到的文件必须已经提交，因为 Claude Code 可能是在一份新克隆的仓库上开工（第一次转话时，脚手架文件也算在内）：请负责人提交，或者请负责人允许你来提交。提交信息写上范围（scope），例如 `docs(plan): F002 方案确认`。

## 10. 什么时候建议开新的 Cowork 会话

一个功能在一个 Cowork 会话里做完：讨论、任务卡、读结果、收尾。下面这些时候，建议换新会话：
- 一个功能收尾了（结果读过，方案状态和任务表已更新）；
- 一件不属于任何功能的事（一次汇报、一批决定）做完了；
- 会话长到前面的内容开始接不上——在下一个稳定点提，不要在讨论到一半时提。

建议之前：把决定和没解决的问题写进 `pipe/cowork/latest.md` 和日志（新会话只知道文件里有的），列出还没提交的改动，再给负责人一句能贴进新会话的开场白，例如「读一下 COWORK.md，然后从 features/F003-csv-export/plan.md 第 3 节接着做 F003」。这只是建议；负责人说继续，就继续。
